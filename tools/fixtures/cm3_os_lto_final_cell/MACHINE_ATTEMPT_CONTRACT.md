# Current CM3 Os-LTO Machine Attempt

`machine_attempt.py` consumes an explicitly named, receipt/manifest-hash-bound
`BUILT-PENDING-READER` batch. It never continues an incomplete producer journal,
reruns a compiler, executes a target, or grants a required-cell credit.

## Admission

Authenticate builder, admission, neutral worker and Os-owned predicate sources
before constructing the current-capture witness. Require the same independently
admitted Native/Reference captures, inventory, source fingerprint, reference
commit, cohort and original opening builder-source registry as the sealed batch.
The builder's original component records, not their pending copies, define the
142-role handoff. Verify the complete artifact membership, hashes, original
input physical identities and captured-source correspondence before replay.

The receipt, aggregate command journal and per-command records are separate
bindings. Worker objects, specs, response bytes and diagnostics must be tied to
the actual command positions and original compilation groups. Stored
`ActualWorker` is a comparison target, not a source of authority for selecting
inputs. The final supported link replaces only the three selected-port objects
in the original nine-object cohort; the other six remain unchanged.

## One Immutable Reader

Snapshot all actual batch artifacts and supplemental native roles before opening
the initially fresh parser. Execute the source-authenticated helpers from the
same frozen module graph used by the actual ELF parser. Inside that graph,
worker reads are allowed only from the admitted lexical path/hash lookup.
No physical path normalization, filesystem enumeration, fresh admission,
process execution or output writes occur inside the reader.

Replay six common and four selected-port compiler-reported worker chains from
their saved WPA/LTRANS arguments, response files, one partition, intermediate,
machine object, original/adapted specs and verbose compiler diagnostics. Preserve
the distinction between compiler-reported execution and OS process tracing.
Recompute the entire port worker record with exact JSON types and ordering.

The machine composer independently inspects twelve common aggregate/worker
images and eight selected-port aggregate/worker/final images. It checks actual
mutant rejection and paired stress activation. The helper result cannot infer
the optimization from ELF bytes; the worker evidence establishes the actual
`-Os` target/options independently.

## Disposition

Unresolved common setter/cold-inline attribution is reported as
`MACHINE-WORKER-REPLAY-PENDING-ATTRIBUTION`. It is not a clean protected-effects
PASS. A fully replayed bounded component result is still
`MACHINE-WORKER-COMPONENTS-REPLAYED-NOT-QUALIFIED`.

Neither disposition proves the complete ABI, isolation, transfer-root,
reference-parity or whole-cell contract. Those still require composition in
the final cell reader. Both dispositions retain zero required-cell credit and
make no archive, hosted-CI, global-freeze, hardware or runtime-execution claim.

Physical opening/closing and sealed result writes stay outside the immutable
reader. Failure or summary-output failure revokes component completion flags.
Recovery may write only the bounded receipt/manifest filenames in the output
directory successfully claimed by this attempt, after checking its original
device/inode identity. No hostile concurrent-filesystem race guarantee is made.

Synthetic tests prove only their declared negative/shape cases. Actual-machine
evidence must be recorded separately with its batch, receipt and manifest SHA256.
No runtime C, assembly, context layout, public-five or mandatory-port-eight API
is changed by this replay tooling.
