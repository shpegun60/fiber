# Current CM3 O2-LTO Selected-Port Build Policy

## Scope

This additive component checks the supported compiler policy for the current
CM3 p4/b16 soft/no-FPU/no-MPU selected port. It is not an attributes-only gate,
an executed firmware test, a FreeRTOS equivalence theorem, or a whole-cell
qualification. The previously qualified common fourteen-body attribute effects
remain separate evidence. No runtime source, assembly, frame or ABI changes are
part of this component.

Admit the actual current slim-LTO capture, its ordinary source-copy authority,
the E9 inventory, exact compiler/plugin/workers, source/header dependencies and
fixed reader/helper buffers before creating output. Preserve the distinction
between original source bytes and actual current LTO object/recipe authority.
Use fresh disjoint managed output, isolated Python (-I -S -B), terminal command
journals, immutable parser snapshots and closing hash/physical checks. Do not
reuse another component's success label or finish predicate.

## Supported Recipe

Compile the actual ARM_CM3 runtime, boot and exception sources unchanged with
their admitted CM3/O2/slim-LTO flags, followed by this raw stress vector:

```text
-finstrument-functions
-fstack-protector-all
-fprofile-arcs
-ftest-coverage
-fsanitize=undefined
-fsanitize-coverage=trace-pc
```

Then append the supported selected-port policy, in this order. Its explicit
trace-pc override extends the older six-option recipe:

```text
-fno-instrument-functions
-fno-stack-protector
-fno-profile-arcs
-fno-test-coverage
-fno-sanitize=all
-fno-sanitize-coverage=trace-pc
-mgeneral-regs-only
```

These overrides are intentional integration requirements, not evidence that
annotations alone suppress hostile code generation. Keep them visible in the
compile and lower recipes. Verify the effective ordered saved WPA/LTRANS
arguments and compiler-reported actual worker commands. GCC may retain both a
positive option and a later negative override; evaluate the ordering instead
of treating mere occurrence as effective enablement. Do not report an OS
process trace from compiler verbose diagnostics.

Discovery and actual compile dependencies must match. Each output must contain
real slim IR, not an executable fat fallback. Lower exactly the three selected
IR providers together with -nostdlib -r -flinker-output=nolto-rel and one LTO
partition. Retain the actual LTRANS machine, its input chain, original REL
metadata and objdump disassembly, not an ordinary recompilation or WPA IR
substitute. Bind aggregate and actual worker output independently.

## Generated-Code Audit

The required roots include all eight mandatory forward operations, both strong
naked exception handlers and their selected-port bridges. Audit every emitted
positive function extent in the selected-only aggregate and its actual LTRANS
machine, including local helpers. Missing mandatory roots, ambiguous aliases,
overlapping extents, uncovered executable bytes and malformed mapping/REL
metadata must not become a narrower inferred successful scope.

Reject instrumentation, stack-protector, gcov, sanitizer, profiler, floating-
point runtime and implicit extended-register dependencies in the audited
machine. Bind actual instruction bytes/mappings and disassembly, and report
precisely which forbidden instruction forms the checker recognizes. A compiler
flag or symbol-prefix scan alone is not a whole-body instruction proof.

The positive REL census admits only ABS32, THM_CALL and THM_JUMP24: complete
nonoverlapping four-byte fields, alignment and actual data/Thumb instruction
sites are checked. It does not prove every C relocation addend or applied
destination. The separate frozen transport reader validates original/applied
references and machine origins for the three complete transfer roots.

Also link the newly compiled three providers into the admitted nine-object
firmware fixture, preserving the other six objects and link script. Audit its
actual machine and final executable with emitted relocations. Record effects
and final root/vector bindings as their own evidence; do not infer original
translation-unit ownership for a coalesced LTO worker. This component does not
replace the independent native/FreeRTOS transfer-protocol join.

The final LTO driver applies the seven counter-options globally. This is a
supported-policy final, not a raw hostile test of common annotations. The six
unchanged input objects are byte-identical; their later generated bodies are
not assumed unchanged. The raw common-attribute component is separate.

## Effective Control

Use one identical ordinary stress source under two recipes: raw options plus
the supported policy, and raw options alone. Its volatile arithmetic/indexing
and retained stack buffer must cause all five requested instrumentation
families in the raw machine. The supported machine must pass the unchanged
clean-effect predicate, and that same predicate must reject the actual raw
machine for the intended effects. Source annotations must not differ between
the two controls. A compile failure, absent function, or ineffectual flag
removal is not a successful negative control.

The raw stress lower may use only the previously specified byte-bounded GCC14
specs adapter that removes automatic -lgcov insertion. Obtain fresh -dumpspecs
from the admitted compiler; retain exact original/adapted bytes and offset.
Do not add instrumentation libraries or stubs, alter other specs bytes, or
cancel any raw stress family. Its worker must actually retain the six positive
options without supported-policy overrides. Keep this distinct from the
supported selected-port lowering, where the overrides are required.
